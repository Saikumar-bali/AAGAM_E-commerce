2. Running the stack locally

# 1. shared packages (types, utils, database) — the dashboard imports them
npm run build --workspace=packages/types
npm run build --workspace=packages/utils
npm run build --workspace=packages/database   # also runs prisma generate

# 2. api-gateway on :3005 against the sandbox database
cd apps/api-gateway
export DATABASE_URL="$AAGAAM_DATABASE" JWT_SECRET=<32+ chars> REDIS_URL=redis://127.0.0.1:6379
# PLAYWRIGHT_QA=true lifts the /auth/login throttle (3/min) so scripted logins don't 429
PLAYWRIGHT_QA=true node dist/src/main.js

# 3. dashboard: /api/* must be proxied to the gateway, and the Mapbox token baked in at build
cd apps/admin-dashboard
cat > .env.local <<'EOF'
NEXT_PUBLIC_API_URL=/api
API_BACKEND_URL=http://127.0.0.1:3005
NEXT_PUBLIC_MAPBOX_TOKEN=pk.<your public token>
EOF
npx next build
NEXT_PUBLIC_API_URL=/api API_BACKEND_URL=http://127.0.0.1:3005 npx next start -p 12000
Two build-time gotchas. NEXT_PUBLIC_API_URL is baked into the client bundle at build time — it must be the same-origin path /api so the browser calls the dashboard's own proxy, not localhost:3005. And NEXT_PUBLIC_MAPBOX_TOKEN must be present during next build; otherwise the rider run console and live-tracking maps render the "Map unavailable – missing Mapbox token" placeholder.

7. RIDER surface (delivery flow)

Login as the rider account → lands on /rider. This is the delivery workspace: offers, the active delivery, subscription delivery runs and the stop-by-stop run console.

Figure 10 — /rider: delivery workspace — pending offers, active delivery and the current delivery card.

Figure 11 — /rider/runs: today's subscription delivery run — one route, individually verified stops, cash held.

Figure 12 — /rider/console: the run console — route progress (3/4 done), per-stop cards (Customer 2 · 0.25 L · ₹399 · Delivered) and the delivery sequence. The map is a live Mapbox canvas when a valid token is baked in.

Figure 13 — /rider/history: terminal outcomes (completed / failed / cancelled / returned) with timestamps and audit detail.

Figure 14 — /rider/pickup: pickup tasks — verify items and quantities, record parcel handoff or report a store-side problem.

Rider delivery flow, end to end. Pickup (/rider/pickup: verify bag → Start run) → route (/rider/runs: open the run) → stop console (/rider/console: Arrive records GPS, then proof — OTP for security-reception, or photo+GPS for personal handover/trusted drop — then Complete, optionally recording COD cash) → accountability (cash batch) → history (/rider/history shows the terminal outcome). Each completion advances the linked order via the shared delivery workflow, not a raw stop update.
