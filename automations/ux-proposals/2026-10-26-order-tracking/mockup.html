Note the state switcher above. All four states were designed, not just the happy path. Loading is a skeleton that mirrors the real layout; empty says there is nothing more to wait for; error keeps the last known status on screen and offers a real way back.

What changed, and why

Each entry is one diagnosis from proposal.md and the change that answers it. Line numbers refer to apps/mobile-customer/src/screens/customer/OrderDetailScreen.tsx. Contrast ratios were computed from the literal hex values; the full table is in §7 of the proposal.

  • P1Live state had no banner. The map panel accepted LIVE (line 388) but the banner switch had no case for it (87–144 → default: null). One state vocabulary now drives both the stamp and the map.
  • P2Primary action below the fold. "Review order" sat after six cards (437, following 447–594). It now lives in a sticky bottom bar, visible without scrolling.
  • P3Tap targets under 44pt. callBtn was ~32pt (paddingVertical: 8, line 703). Every control is now ≥ 48pt.
  • P4The rider's number was never shown. It was used only to build a tel: URL (427). The number is now printed as text beside the call action.
  • P5"Rider" appeared twice. Once as the map's riderLabel (418) and once in the banner (103). There is now one rider block.
  • P6Labels failed contrast. #94A3B8 is 2.56:1 on white (716, 736). The muted token is now #5C6B68 — 5.08:1 on paper, 5.59:1 on white.
  • P7Hero label missed AA. #99F6E4 on #0F766E is 4.34:1 (619, used 337). The hero is re-cut to ink on paper: 7.47:1 and 16.05:1.
  • P8Money was ambiguous. "Funded delivery ₹0" (337–338, orderPresentation.ts:47) is now a sentence: "Have ₹130 ready in cash." / "Nothing to pay."
  • P9Future-tense copy on delivered orders. The schedule card always said "Your store prepares this order…" (348–354). Copy is now status-aware.
  • P10Raw enums and "N/A". PENDING_COD (580–585) now reads "Cash on delivery"; N/A is replaced by a sentence with a next step.
  • P11Timestamps used the device locale. toLocaleString() at 336 and 467 vs the deliberate en-IN/Asia/Kolkata formatting in deliveryWindow (32–47). One formatter now.
  • P12Empty timeline rendered an empty card. timeline || [] (449) produced a titled card with no body. It now has a real empty state.
  • P13Error was a dead end. One sentence, no retry (284–290), despite refetch existing (156). Now: Try again, an offline explanation and the last known status.
  • P14Loading was a bare spinner. (277–283). Now a skeleton that mirrors the real layout, with an announced status.
  • P15No offline handling. NetInfo is absent from the app entirely. A connection ribbon now shows when updates stop arriving, with the age of the last one.
  • P16The code's instruction was above its action. Copy at line 99 sat above the reveal button at 128. The instruction now sits with the control, and the code panel is labelled.

What is deliberately unchanged

The redesign keeps the brand teal (#0F766E) and every existing token name. Teal is demoted from full-bleed background to ink — that is the whole move. The whole DeliveryCodeCard is reused as-is, including its 44pt+ buttons and expiry countdown. Socket wiring, the 10s polling backstop, the testIDs and the en-IN money formatting are all preserved.

Not verified

This is a mockup, so nothing here has been through a device. Before shipping I would confirm: that the gateway actually emits a LIVE tracking state (I inferred it from line 388); contrast measured on a real panel rather than from hex; VoiceOver/TalkBack traversal and focus order, since native reads accessibilityLabel rather than DOM semantics; behaviour at 200% text size; and the real payloads for live, delivered and cancelled orders. The full list is §5 of the proposal.
