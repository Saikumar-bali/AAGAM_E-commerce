Rider COD ledger — Cash Book

A redesign of RiderCodScreen.tsx, the rider's cash-accountability ledger. Same data contract (GET /riders/portal/cod), same behaviour, different presentation: a ruled petty-cash book instead of floating cards. Every number sits in a column, every status is a stamp, and variance is a signed figure with a plain-language meaning.

13 diagnosed problems · P1–P13 4 states + offline 360px & desktop mockup only · no app code changed

Problem key

  1. P1 Labels set at 9–10px (five uses of fontSize: 9) — below a legible floor.
  2. P2 #A7F3D0 on #0F766E = 4.27:1 — header and hero labels fail AA.
  3. P3 Variance printed as an unsigned figure with no meaning or next step.
  4. P4 Error state has no retry button, only "pull down".
  5. P5 Raw exception message leaked into the UI.
  6. P6 No offline handling; NetInfo is not even a dependency.
  7. P7 Filter chips minHeight: 38 — under the 44pt touch floor.
  8. P8 Chips are raw enum labels ("HELD", "PARTIAL") the rider must translate.
  9. P9 Loading shows a bare spinner and a false ₹0.00 held-cash balance.
  10. P10 Empty state assumes a filter is active; a new rider sees the wrong message.
  11. P11 Variance colour duplicated; the warning prop renders danger.
  12. P12 Policy paragraph sits below the buttons it describes.
  13. P13 The deposit task is stated but has no action, and no reference to copy.

Static mockup, no build step, no dependencies beyond one Google Fonts link. Shipped application code is unchanged; see proposal.md for the evidence table, the token diff and the pre-ship verification list.
